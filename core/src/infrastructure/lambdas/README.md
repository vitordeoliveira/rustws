# Lambda Infrastructure

This directory contains the infrastructure layer for managing lambda functions in RUSTWS Core.

## Directory Structure

```
lambdas/
├── mod.rs           # Lambda storage management module
├── README.md        # This documentation file
├── source/          # Lambda function source code (includes examples)
└── wasm/            # Compiled WASM files
```

## Directory Purposes

### `source/`

Contains the source code for lambda functions before compilation to WASM:

- **Rust functions**: `function_name.rs`
- **AssemblyScript**: `function_name.as`
- **C/C++**: `function_name.c` or `function_name.cpp`
- **Go**: `function_name.go`
- **Other WASM-compatible languages**
- **Examples**: Reference implementations and templates

### `wasm/`

Contains compiled WASM files ready for execution:

- **Naming convention**: `{lambda_id}.wasm`
- **Generated by**: Build tools, compilation pipelines
- **Used by**: wasmer runtime engine

## Lambda Function Lifecycle

1. **Development**: Write source code in `source/`
2. **Compilation**: Compile to WASM using appropriate toolchain
3. **Storage**: Store compiled `.wasm` file in `wasm/` directory
4. **Registration**: Register lambda metadata in business logic layer
5. **Execution**: Run via wasmer engine

## Supported Runtimes

- **Rust**: Compile with `wasm32-unknown-unknown` target
- **AssemblyScript**: TypeScript-like syntax for WASM
- **C/C++**: Compile with emscripten or wasi-sdk
- **Go**: Compile with TinyGo for WASM
- **JavaScript**: Via QuickJS WASM runtime

## File Naming Conventions

### Source Files

- Use descriptive names: `user_authentication.rs`
- Include runtime extension: `.rs`, `.as`, `.c`, `.go`
- Use snake_case for consistency

### WASM Files

- Use UUID from lambda metadata: `{uuid}.wasm`
- Automatically managed by storage layer
- Direct correlation to database records

## Example Usage

```rust
use crate::infrastructure::lambdas::LambdaStorage;

let storage = LambdaStorage::new();

// Save source code
storage.save_source("hello_world", source_code, "rs").await?;

// Save compiled WASM
let lambda_id = Uuid::new_v4();
storage.save_wasm(lambda_id, wasm_bytes).await?;

// Load for execution
let wasm_data = storage.load_wasm(lambda_id).await?;
```

## Development Workflow

1. **Create** lambda function in `source/`
2. **Test** locally with appropriate runtime
3. **Compile** to WASM format
4. **Upload** via RUSTWS Core API
5. **Deploy** and execute via lambda service

## Security Considerations

- Source code is stored for auditing and recompilation
- WASM files are sandboxed during execution
- File access is restricted to lambda directories
- No network access from filesystem layer
